# 《高光谱数据预处理主流程》代码框解读

对应文件：`notebooks/高光谱数据预处理主流程.ipynb`。

本文按 Notebook 中从上到下的 16 个代码框说明：运行了什么、输出代表什么、可以得到什么数据认识，以及不能据此得出什么模型结论。

## 阅读原则

- 文本中的“训练集”是 `fair24_6_70` 的 10,265 个训练中心像元；
- “验证集”有 2,567 个中心像元，用于以后选择超参数；
- “测试集”有 29,944 个中心像元，当前不计算预测与性能；
- split 数量和空间成员位置属于冻结的实验设计，可以展示全部 split；
- 光谱曲线、PCA/LDA 散点、代表性 patch 和 batch 内容只分析训练集；
- PCA 方差比与 LDA 判别解释比都不是分类准确率，肉眼可分也不等于模型一定能正确分类。

本说明后面的实际数值仍对应统一 YAML 默认的 PCA15 路线。若只在 `Pavia数据预处理.yaml` 中把 `reducer: pca` 改为 `reducer: lda`，执行顺序完全不变，但会出现以下差异：输出波段数由 15 变为 8，单样本 patch 由 `(1,15,25,25)` 变为 `(1,8,25,25)`，解释比图和二维散点的标题自动改为 LDA。LDA 使用训练光谱和训练标签拟合，验证/测试标签不参与拟合。

## 代码框 1：定位项目与检查运行环境

### 做了什么

寻找包含 `pyproject.toml` 的项目根目录，把它加入 Python 模块路径，导入 PyTorch、数据工作流函数和绘图函数，并检查 CUDA。

### 当前输出

```text
项目根目录：<你的仓库目录>
PyTorch：2.12.1+cu130
CUDA 可用：True
```

### 含义

- 路径正确表示 Notebook 正在使用固定实验工作区；
- `2.12.1+cu130` 表示 PyTorch 带 CUDA 13.0 支持；
- `CUDA=True` 表示后续模型可以使用 RTX 5070。

这一框只检查环境，没有载入数据，也没有发生 GPU 训练。如果项目路径错误、PyTorch 版本不符或 CUDA 为 False，应先停止后续模型实验。

## 代码框 2：读取 YAML 配置

### 做了什么

读取唯一日常入口 `Pavia数据预处理.yaml`，生成 `WorkflowSettings`。默认选择为 `fair24_6_70 + PCA15 + patch25`。

### 关键输出

```text
fair24_6_70__seed345__standard_pca15_patch25
standard + pca15 + patch25
batch_size=256
loader_seed=42
```

### 含义

- `fair24_6_70`：24% 训练、6% 验证、70% 测试；
- `seed345`：数据划分固定随机种子；
- `standard`：逐波段标准化；
- `pca15`：103 个原始波段降到 15 个主成分；
- `patch25`：每个中心像元提取 25×25 空间邻域；
- `batch_size=256`：DataLoader 每批最多返回 256 个样本；
- `loader_seed=42`：训练样本打乱顺序可复现。

`WorkflowSettings(...)` 的长输出只是所有参数的完整对象表示，不是实验结果。冻结状态目录存在只说明参数文件可以被定位，还没有证明其内容正确；该检查由代码框 7 完成。

## 代码框 3：读取原始影像、标签和固定划分

### 数据形状

```text
数据立方体：(610, 340, 103)，uint16
标签图：(610, 340)
总像元：207,400
有标签像元：42,776（20.62%）
背景或未标注：164,624（79.38%）
```

`610×340` 是空间尺寸，`103` 是每个像元的光谱数值个数。`uint16` 是原始传感器数值类型，不是模型最终输入类型。标签 0 表示背景或未标注，只有标签 1–9 的 42,776 个像元进入固定划分。

### 划分数量

```text
训练：10,265
验证： 2,567
测试：29,944
```

三者相加正好等于 42,776。实际比例为 24%、6%、70%。

### 类别不均衡

九类总量中：

- 草地 Meadows：18,649 个，是最大类别；
- 阴影 Shadows：947 个，是最小类别；
- 最大类约为最小类的 19.7 倍。

这说明后续只报告 OA 会偏向大类别。正式结果还应包含 AA、逐类准确率和混淆矩阵。是否使用类别权重或平衡采样，必须以后在验证集上比较，不能因为这一张表就直接宣称某种策略更好。

## 代码框 4：验证固定划分与两协议关系

### 预期输出

```text
current_disjoint=True
current_full_coverage=True
current_class_coverage=True
current_coordinate_label_alignment=True
same_sample_identity=True
shared_test_set=True
fair_train_plus_validation_equals_paper_train=True
```

### 含义

- `current_disjoint`：当前 train/validation/test 没有重复中心像元；
- `current_full_coverage`：全部 42,776 个有标签像元恰好出现一次；
- `current_class_coverage`：每个非空 split 均包含九个类别；
- `current_coordinate_label_alignment`：保存的二维坐标与原标签图一致；
- `same_sample_identity`：两协议使用相同的有标签像元编号、坐标与标签；
- `shared_test_set`：`paper30` 和 `fair24_6_70` 测试集完全相同；
- 最后一项：fair 的训练集和验证集合并后恰好等于 paper30 的训练池。

如果当前 Notebook 中该框还没有保存输出，是因为它是在上次运行后新加入的。单独运行这一框即可看到上述结果。源文件哈希和同 seed 重建由自动测试与 `scripts/验证固定划分.py` 负责。

## 代码框 5：划分数量图与空间分布图

### 左右柱形图

总体柱形图确认 24%/6%/70%；逐类柱形图显示每个类别也近似维持相同比例，因此这是分层划分。草地在三个 split 中都最多，阴影最少，说明分层保持了原始类别比例，但没有消除类别不均衡。

### 空间图

蓝、橙、灰三种中心像元在同一地物区域内呈细碎交错分布，而不是分成独立空间块。这是逐像元分层随机划分的典型特征。

其重要含义是：训练中心和测试中心虽然不同，但 25×25 patch 可能互相重叠。由此得到的随机像元实验适合论文兼容复现，但可能比严格空间块划分更乐观。最终论文应披露这一限制，后续可增加空间块划分作为泛化对照。

## 代码框 6：训练集九类原始光谱统计

### 图中元素

- 实线：该类别训练像元在每个原始波段上的平均值；
- 阴影：平均值上下一个标准差；
- 横轴：1–103 的波段编号，不是实际波长；
- 每个面板只使用训练集，不读取验证或测试光谱。

### 实际可见现象

- 涂漆金属板的整体响应较高，早期波段形成明显峰形；
- 草地、树木和裸土在后段波段出现明显上升，但曲线形状和幅度不同；
- 阴影整体响应很低，曲线形态与多数类别不同；
- 沥青路面、沥青材料、自锁砖和部分砾石曲线存在相似区域；
- 多个类别的标准差范围较宽，说明同一类别内部仍有光照、材质或空间差异。

各子图纵轴会自动缩放，不能只凭视觉高度直接跨面板比较绝对数值。这些曲线可用于提出“某些波段可能更有判别力”的假设，但不能直接证明波段选择或分类性能。

## 代码框 7：加载冻结的标准化和 PCA 参数

### 关键输出

```text
拟合样本：10,265（train only）
验证/测试参与拟合：False
输出光谱维数：15
```

这一步不是重新运行 PCA，而是读取已经保存的训练集均值、标准差、PCA 方向和元数据。`False` 是无数据泄漏的重要证据：验证和测试像元没有参与参数估计。

此时 pipeline 已经知道如何把 103 维映射到 15 维，但完整影像尚未真正变换。

## 代码框 8：变换完整高光谱立方体

### 输出

```text
(610, 340, 103) → (610, 340, 15)
dtype=float32
全部数值有限=True
```

空间位置完全不变，只把每个像元的光谱描述从 103 维变为 15 维。使用训练集拟合好的参数去 `transform` 验证、测试和背景像元是允许的；泄漏发生在用它们重新 `fit`，而这里没有 fit。

`float32` 是深度学习常用精度；“全部数值有限”说明没有 NaN 或无穷大。变换后的完整立方体保存在内存中，没有把全部 patch 重复写到磁盘。

## 代码框 9：原始波段、第一主成分与标签图对照

### 原始第 51 波段

灰度图能够看到道路、建筑、草地区域等空间结构，但单个波段对某些材质的区分能力有限。

### 第一主成分

第一主成分是 103 个标准化波段的线性组合。图中仍保留了道路、建筑边缘和大面积地物结构，并增强了部分区域之间的对比，说明 PCA 没有破坏主要空间结构。

### 标签图

不同颜色对应类别 1–9，大面积背景为标签 0。标签只覆盖部分区域，所以 79.38% 的空间位置不会作为有监督中心样本。

第一主成分不对应某个真实波长，颜色也不是自然颜色；这组三图是数据内容预览，不是分类图或预测结果。

## 代码框 10：PCA 解释方差

### 实际图形

- 第一主成分约解释 63% 方差；
- 第二主成分约解释 29%；
- 第三主成分约解释 6%；
- 前三项已经保留绝大多数方差；
- 15 个主成分累计解释方差为 99.9247%。

这说明原 103 个波段高度相关，PCA15 在压缩计算量的同时保留了几乎全部训练数据方差。后面分量的柱子很小不代表它们对小类别一定无用，因为“总体方差大”与“类别判别力强”不是同一个目标。

## 代码框 11：训练集 PCA-1/PCA-2 散点

### 实际可见现象

- 阴影在左下区域形成相对独立的紧密簇；
- 涂漆金属板向右上方形成明显延伸，与大多数类别较容易区分；
- 树木主要位于左侧较高的第二主成分区域；
- 沥青路面、砾石、裸土、自锁砖和部分草地在中心区域明显重叠；
- 个别离群点可能来自类别边界、混合像元或异常光谱。

图中每类最多固定抽取 500 个训练样本，所以点数不是类别总量。前两主成分只追求最大方差，不保证分类最优；二维重叠不等于 HybridSN 无法区分，因为模型还会使用 15 个主成分和 25×25 空间上下文。

## 代码框 12：构造 PyTorch Dataset

### 关键输出

```text
train Dataset：10,265
validation Dataset：2,567
test Dataset：29,944
首个训练输入：(1, 15, 25, 25)
sample_index=3
coordinate=(0, 94)
raw_label=1
model_label=0
```

单样本 `(1,15,25,25)` 的含义依次为：输入通道、PCA 光谱深度、patch 高度、patch 宽度。首个样本位于第 0 行、第 94 列，因此靠近影像上边界，Dataset 会使用既定 padding 保证仍返回完整 25×25 patch。

`raw_label=1` 是数据集原标签，`model_label=0` 是交叉熵需要的零基类别编号。二者相差 1 是预期契约。

打印出的字典形状中，`label/raw_label/sample_index` 是标量，所以显示 `()`；坐标有行列两个值，所以显示 `(2,)`。Dataset 按访问动态提取 patch，没有一次性把全部 42,776 个 patch 复制进内存或磁盘。

## 代码框 13：九类代表性训练 patch

每个面板从相应类别训练坐标附近选择一个代表样本，并显示第一主成分上的 25×25 邻域；红色加号是当前需要分类的中心像元。

实际图中能看到：

- 草地、树木、阴影等样本具有明显的大块区域与边界；
- 涂漆金属板、沥青路面、自锁砖等样本包含较强的人工结构、线条或局部亮点；
- 有些中心像元位于类别边界附近，邻域可能同时包含多种地物外观。

这说明空间上下文对分类有价值，也是使用 CNN/HybridSN 而不只使用中心光谱的原因。每类只展示一个 patch，不能代表整个类别；而且每个子图的颜色范围由 Matplotlib 独立缩放，不能直接用颜色亮暗跨子图比较绝对 PCA 数值。

## 代码框 14：构造 PyTorch DataLoader

### 输出

```text
batch_size=256
loader_seed=42
num_workers=0
pin_memory=True
train：41 batches
validation：11 batches
test：117 batches
```

批次数是向上取整：例如 10,265÷256 得到 40 个完整批次加 1 个较小批次，所以是 41。`drop_last=False` 保证最后一个不满 256 的批次不会丢失。

训练集使用 seed=42 可复现打乱；验证和测试保持固定顺序。`num_workers=0` 在当前 Windows/Jupyter 环境最稳定；`pin_memory=True` 有利于后续把 CPU batch 搬到 GPU，但这一框本身没有进行 GPU 训练。

## 代码框 15：检查正式模型将接收的 batch

### 输出形状

```text
input：(256, 1, 15, 25, 25)，float32
label：(256,)，int64
raw_label：(256,)
coordinate：(256, 2)
sample_index：(256,)
```

第一个维度 256 是 batch 样本数，后四维与单样本一致。模型以后主要读取 `input` 和 `label`；其余字段用于把预测追溯到原始标签和二维位置，以及生成分类图。

`标签映射正确=True` 表示该批次每个 `raw_label` 都等于 `label+1`。这只验证数据接口，不表示模型已经产生预测。

## 代码框 16：首个训练 batch 的类别构成

### 当前实际计数

```text
类别1 沥青路面：43
类别2 草地：100
类别3 砾石：13
类别4 树木：16
类别5 涂漆金属板：10
类别6 裸土：35
类别7 沥青材料：12
类别8 自锁砖：26
类别9 阴影：1
合计：256
```

该批次基本反映全训练集的不均衡：草地很多，阴影极少。由于 DataLoader 只是随机打乱而没有采用平衡采样，每个 batch 不会保证各类相同；seed=42 固定后，第一次运行可复现这一首批构成。

单个 batch 不能代表整个训练集，也不是 24%/6%/70% 的 split 比例。它提示后续可将类别权重、平衡采样或 focal loss列为候选方案，但是否采用必须通过 `fair24_6_70` 验证集实验决定。

## 当前阶段可以得出的总体结论

1. 数据和固定划分有效，`fair24_6_70` 提供独立验证集；
2. Pavia University 类别明显不均衡；
3. 逐像元随机划分存在空间邻域重叠风险，需在论文中披露；
4. 103 个波段冗余较强，PCA15 保留 99.9247% 训练方差；
5. 仅 PCA 前两维不能完全分开九类，空间 patch 有进一步建模价值；
6. PyTorch 最终输入接口已经固定为 `N×1×15×25×25`；
7. 当前仍没有正式模型预测、OA、AA、Kappa 或混淆矩阵。

下一阶段应在独立 Python 模型文件中实现 HybridSN，并先做结构、shape 和参数量测试，而不是在本 Notebook 中加入正式训练循环。
